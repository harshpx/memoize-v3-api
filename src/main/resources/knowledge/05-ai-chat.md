# AI Chat & Conversations

## Overview

The AI Chat feature provides conversational AI interactions using Google Gemini models. It supports streaming responses, conversation management, vector-store-based memory for context-aware conversations, and **RAG (Retrieval-Augmented Generation)** for answering questions about the application itself using the knowledge base.

---

## 1. Conversations

### Entity: Conversation

| Field          | Type        | Description                                    |
|----------------|-------------|------------------------------------------------|
| id             | UUID (PK)   | Auto-generated unique ID                       |
| name           | String(100) | Conversation title (auto-generated or "New Chat") |
| isProperName   | boolean     | Whether the name was AI-generated              |
| isNew          | boolean     | Marks a freshly-created empty conversation     |
| user           | User (FK)   | Owner of the conversation                      |
| createdAt      | LocalDateTime | Creation timestamp                           |
| updatedAt      | LocalDateTime | Last update timestamp                         |

### Conversation Lifecycle

```
[Create] --> [First Query] --> [Name Auto-Generation] --> [Subsequent Queries] --> [Delete]
```

1. **Create**: A new conversation is created with name "New Chat", `isNew=true`, `isProperName=false`
2. **First Query**: When the user sends their first message, the response is saved and the conversation name is auto-generated by the LLM
3. **Name Generation**: The `simple-gemini-3.1-flash-lite` model generates a 3-5 word title based on the query+response
4. **Subsequent Queries**: The system uses the appropriate `ChatClient` (with memory and optionally RAG) to answer with context
5. **Delete**: Conversation + all associated chats + vector store memory are deleted

### API Endpoints

| Method   | Endpoint                   | Description                                   |
|----------|----------------------------|-----------------------------------------------|
| POST     | /ai/conversation           | Create new empty conversation                 |
| POST     | /ai/conversation/all       | Get all conversations for user                |
| GET      | /ai/conversation/{id}      | Get specific conversation by ID               |
| DELETE   | /ai/conversation/{id}      | Delete conversation + associated memories     |

**Note:** Calling `/ai/conversation/all` automatically creates a new conversation if none exists (auto-create behavior).

## 3. LLM Query (Streaming)

### The Streaming Pipeline

```
[User Query] --> POST /ai/chat/{conversationId}?query=...
      |
      v
[ChatServiceImpl.queryLlmStream()]
      |
      ├── 1. Validate conversation exists & belongs to user
      ├── 2. Save user message as Chat (type=QUESTION) in DB
      ├── 3. Check if query needs knowledge base via RagService
      │      ├── YES → Use "memory-rag-gemini-3.1-flash-lite" (memory + docs)
      │      └── NO  → Use "memory-gemini-3.1-flash-lite" (memory only)
      ├── 4. Stream response via selected Gemini model (30s timeout)
      │
      ├── [ON STREAM COMPLETE]:
      │   ├── Save AI response as Chat (type=ANSWER) in DB
      │   └── If conversation name not set (isProperName=false):
      │       └── Use simple model to generate name (3-5 words)
      │
      └── [ON ERROR]:
          └── Return "Error generating response" as fallback
```

### LLM Clients Used

| Bean Name                       | Model                     | Memory | RAG | Purpose                        |
|---------------------------------|---------------------------|--------|-----|--------------------------------|
| `simple-gemini-3.1-flash-lite` | gemini-3.1-flash-lite     | ❌     | ❌  | Conversation name generation    |
| `memory-gemini-3.1-flash-lite` | gemini-3.1-flash-lite     | ✅     | ❌  | General chat (no knowledge)     |
| `memory-rag-gemini-3.1-flash-lite` | gemini-3.1-flash-lite | ✅     | ✅  | App-related queries (with docs) |
| `memory-gemini-3.5-flash`      | gemini-3.5-flash          | ✅     | ❌  | Reserved / future use           |
| `memory-rag-gemini-3.5-flash`  | gemini-3.5-flash          | ✅     | ✅  | Reserved / future use           |

### Chat Client Selection Logic

In `ChatServiceImpl`, the system dynamically selects the appropriate chat client:

```java
ChatClient chatClient = ragService.requireKnowledgeStore(query) 
    ? docAndMemoryChatClient   // memory-rag-gemini-3.1-flash-lite
    : memoryChatClient;        // memory-gemini-3.1-flash-lite
```

- `RagService.requireKnowledgeStore()` searches the `knowledge_vector_store` with a similarity threshold of 0.65
- If relevant documentation chunks are found, the query is considered **app-related** and the RAG-enabled client is used
- Otherwise, the memory-only client handles the query

### Response Format

The response is a **Server-Sent Events (SSE)** stream:
```
Content-Type: text/event-stream

data: Hello
data:  how
data:  can
data:  I
data:  help
data:  you?
```

### Chat Memory

- Uses **pgvector** with `chat_memory_vector_store` table
- Stores embeddings of past conversations
- Retrieves last 5 relevant exchanges for context
- Distance metric: COSINE_DISTANCE
- Index type: HNSW

### RAG (Knowledge Base)

- Uses **pgvector** with `knowledge_vector_store` table
- Contains chunked and embedded documentation from `classpath:knowledge/*.md`
- Similarity threshold: 0.65 (RagService) / 0.55 (QuestionAnswerAdvisor)
- Documents are indexed incrementally on application startup

## 4. Name Auto-Generation

When a new conversation receives its first AI response, the `onLLMSuccessHandler` triggers:

1. **Check**: If `isProperName == false`, generate a name
2. **Prompt**: Send the first query + first response to simple chat client
3. **Rules**: 3-5 words, plain text, no quotes/punctuation
4. **Update**: Save the generated name and set `isProperName=true`, `isNew=false`

### Example Names Generated

| Query                                | Generated Name              |
|--------------------------------------|-----------------------------|
| "Explain how Java Streams work"      | Java Stream Explanation     |
| "How do I manage React state?"       | React State Management      |
| "Write a SQL join query"             | SQL Join Basics             |

## 5. Async Architecture

### LLM Task Executor

```yaml
Core Pool Size: 4
Max Pool Size: 16
Queue Capacity: 100
Keep Alive: 30 seconds
Thread Name Prefix: "LLMAsync-"
Shutdown: Wait 15s for tasks to complete
Rejection Policy: CallerRunsPolicy
```

### Why Async?

- LLM calls are **blocking I/O** operations (network calls to Google Gemini API)
- The stream processing is **reactive** (Project Reactor)
- Chat persistence and name generation run **asynchronously** to avoid blocking the response stream

## 6. Chat Persistence Service

### ChatPersistanceService

A dedicated service for persisting chat data in separate transactions:

| Method              | Propagation  | Description                            |
|---------------------|-------------|----------------------------------------|
| `saveChat()`        | REQUIRES_NEW | Saves a chat message in its own transaction |
| `setConversationName()` | REQUIRES_NEW | Updates conversation name independently |

Using `REQUIRES_NEW` ensures that even if the main LLM operation fails, the chat messages already streamed to the client are still saved.

## 9. Frontend Integration

### MemoAI Page UI

The frontend provides a dedicated **MemoAI** page accessible from the sidebar/dock. The layout consists of:

**Desktop Layout:**
```
┌──────────────────────────────────────────────────────┐
│ [← Conversation Drawer]  [Chat Area]                  │
│                          │                             │
│  Conversation List       │  Chat Messages              │
│  ┌─────────────────┐   │  ┌────────────────────────┐ │
│  │ New Chat (+)     │   │  │ Welcome message        │ │
│  ├─────────────────┤   │  │ User: "Hello"           │ │
│  │ Chat 1           │   │  │ AI: "Hi there! ..."    │ │
│  │ Chat 2           │   │  │  (streaming response)  │ │
│  │ Chat 3           │   │  └────────────────────────┘ │
│  └─────────────────┘   │  [Input box] [Send button]   │
└──────────────────────────────────────────────────────┘
```

**Empty State (No Conversations):**
- Welcome screen: *"Hi [name]! Ask Memo AI anything."*
- "New Chat" button prominently displayed

### Starting a Conversation

1. Navigate to **MemoAI** from the sidebar/dock
2. Click **"New Chat"** button (or "+" icon) to create a new conversation
3. The conversation appears in the conversation list with name "New Chat"
4. If an unsaved "new" conversation already exists, the system switches to it instead of creating another duplicate

You can also start a chat from the **Dashboard** by clicking the **"Ask MemoAI"** button.

### Sending Messages

1. Type your question in the text input box at the bottom of the chat screen
2. Press **Enter** (or click the **Send** button) to submit
3. Use **Shift+Enter** to add a new line without sending
4. While the AI is generating a response, the input box is disabled

### Streaming Response UX

When MemoAI generates a response:
- **Real-time streaming**: Response text appears character-by-character via SSE
- **Timer indicator**: Shows *"3s ..."* with animated dots while the AI processes
- **Input disabled**: The text input is disabled during streaming
- **Completion**: Input re-enables, and the conversation name may auto-update

### Conversation Management (Frontend)

- **Conversation Drawer**: Hamburger menu icon at the top left opens the drawer listing all conversations
- **Switching**: Click any conversation name in the drawer to switch to it (highlighted when active)
- **Deleting**: Conversations can be deleted from the drawer via a delete action; a toast confirms deletion
- **Auto-Naming**: After the first exchange, the frontend polls for the conversation name to update automatically

### UI States

| State | Frontend Behavior |
|-------|-------------------|
| **Loading (Conversations)** | Skeleton placeholders in the conversation drawer |
| **Loading (Chat Messages)** | Skeleton placeholders while fetching chat history |
| **Empty (No Messages)** | Welcome screen with prompt to start chatting |
| **Streaming Response** | Character-by-character text appearing + "3s ..." timer + disabled input |
| **Error (Failed Response)** | Toast notification: "Failed to get response" |
| **Conversation Deleted** | Toast confirmation + redirect to empty state or next conversation |
